# Chapter 16: Google Search Console

## Core Idea
GSC 是来自 Google 的第一手免费数据——监控搜索表现、索引状态、抓取错误和页面体验，所有网站必须尽早验证并养成定期检查的节奏。

## Frameworks Introduced
- **GSC 核心功能地图**: 六大报告——①搜索结果报告（点击/展示/CTR/平均排名）；②网页索引报告（已索引/未索引/错误）；③Sitemap 报告（提交与状态）；④链接报告（外链/内链/锚文本）；⑤核心网页指标（LCP/FID/CLS）；⑥移动设备易用性。何时用：搭建 SEO 监控的第一站。
- **四大验证方法**: HTML 文件上传到根目录、HTML meta 标签加到首页 `<head>`、复用 Google Analytics 账号验证、复用 Google Tag Manager 验证。何时用：添加属性后任选其一。
- **页面未被索引排查流**: URL 检查工具查状态 → 检查 robots.txt → 检查 noindex 标签 → 检查 canonical 标签 → 修复后请求编入索引 + 提升内容质量。
- **问题处理优先级**: 手动惩罚（立即）> 索引错误（尽快）> 抓取错误（定期）> 体验问题（持续优化）。

## Key Concepts
- **点击次数/展示次数/CTR/平均排名**: 搜索结果报告的四个关键指标，CTR = 点击/展示。
- **URL 检查工具**: 查看单个 URL 的索引状态、抓取信息和渲染结果，可"请求编入索引"加速收录。
- **软 404**: 页面返回 200 但内容实际是"不存在"，属于常见索引问题之一。
- **数据延迟**: GSC 数据通常延迟 2-3 天。
- **手动操作报告**: 查看手动惩罚、了解原因、提交重新审核的入口。

## Mental Models
- 把 GSC 当"搜索世界的体检报告"：它统计的是搜索展示和点击（发生在用户到站之前），与 GA 的到站访问数据互补。
- 用"高展示低点击"找优化点：这类查询的标题和描述有问题，是 CTR 优化的第一靶子。
- 把 Sitemap 当"规范页面清单"：只包含 canonical 页面，及时更新，定期检查处理状态。

## Anti-patterns
- **只在流量出事时才开 GSC**: 应每周看搜索结果报告、每月看索引和链接报告、每季度全面检查。
- **Sitemap 塞了非规范页或过期 URL**: 造成索引浪费和状态混乱。
- **发现 404 不处理**: 应修复或做重定向，优化重定向链。
- **GSC 数据延迟误判为事故**: 2-3 天延迟是正常的，别把延迟当流量暴跌。

## Worked Example
流量下降 20% 的排查：①搜索结果报告——确认流量降、部分关键词排名和 CTR 下降；②网页索引报告——发现未索引页面增加、抓取错误增加、出现服务器错误；③归因——服务器不稳定导致抓取错误，部分页面被误加 noindex，内容质量下滑；④实施——修服务器、移除 noindex、优化内容；⑤监控效果。结果：流量增长 30%，排名恢复，索引页面回升。

## Reference Tables
核心网页指标三类状态：良好 / 需改进 / 不达标，覆盖 LCP（加载性能）、FID（交互性）、CLS（视觉稳定性）。

移动设备易用性常见问题：文字太小难阅读、可点击元素太近、内容超出屏幕、视口未设置。

常见抓取错误与对策：5xx→修服务器；404→修复或重定向；重定向问题→优化重定向链。

## Key Takeaways
1. GSC 是 SEO 必备工具，先验证再谈优化。
2. 搜索结果报告的黄金动作：找高展示低点击的查询优化标题描述。
3. 索引报告盯"未编入索引"的原因分类，逐类修复。
4. URL 检查工具是加速新页面收录的正道（配合内链和高内容质量）。
5. 处理优先级：手动惩罚 > 索引错误 > 抓取错误 > 体验问题。
6. GSC 与 GA 数据口径不同，不一致属正常。
