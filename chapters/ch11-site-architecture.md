# Chapter 11: 网站架构

## Core Idea
好的网站架构 = 扁平层级（所有页面 3 次点击内可达）+ 清晰内链 + 规范 URL + 面包屑导航。架构决定爬虫效率和权重分配，是内容和外链的地基。

## Frameworks Introduced
- **扁平 vs 层级架构选择**：扁平（首页直连所有页面）适合小站；层级（首页→分类→内容）适合大站；推荐"扁平化层级"——层级组织但深度控制在 3 层内。
- **3 层点击深度规则**：比常见的"5 次点击"更严格——重要页面 2 次点击内、所有页面 3 次点击内到达。实操：把深度转化为宽度，参考 Toolify 的 footer 直接列出所有重要分类链接。
- **子域名 vs 子目录决策表**：同一主题的不同页面 → 子目录（共享权重）；完全不同的关键词领域 → 子域名（Google 视子域名为独立站点，关键词聚焦更紧密）。
- **内链四法**：相关内容推荐（页尾/侧栏）、面包屑导航、首页链接最新最热内容、分类页列出全部内容。每页 3-5 个描述性内链。
- **URL 层级设计**：`/category/subcategory/page`，小写 + 连字符 + 简短 + 含关键词 + 避免参数。
- **Sitemap 约束**：只含规范页、更新 lastmod、单文件 ≤50MB / 50,000 URL、提交 GSC。

## Key Concepts
- **页面深度（Click Depth）**：从首页到某页的点击次数，影响抓取效率、权重分配和用户体验。
- **扁平架构 / 层级架构**：两种基本组织方式，分别适合小站和大站。
- **面包屑导航**：显示当前位置的导航（含 BreadcrumbList 结构化数据），同时服务用户和爬虫。
- **内链权重传递**：内链是权重在站内流动的管道，重要页面应获得更多内链。
- **XML / HTML Sitemap**：给爬虫的页面清单 / 给用户的页面目录。
- **子域名独立性**：Google 将子域名视为独立站点——onl.jp 案例的核心手段。
- **后端渲染强制**：架构再好，爬虫看到空 body 一切归零（Googlebot 不为小站执行 JS）。

## Mental Models
- 把架构当"地铁线路图"：站点越像"从任何站出发 3 站可达核心区"，爬虫和用户越高效。
- 把内链当"水管系统"：权重从首页流入，深度越深、分支越乱，末端水压（权重）越低。
- 把"深度"兑换成"宽度"：降不了层级就在 footer/分类页加链接面。

## Anti-patterns
- **页面埋得太深**（4+ 层点击）：爬虫效率低、权重衰减、用户找不到。
- **参数化 URL**（index.php?id=123&cat=456）：可读性差、易重复内容。
- **内链混乱或孤岛页面**：无内链的页面基本不会被收录。
- **纯前端渲染**：架构设计再好，Googlebot 看到空 body 全部白费。
- **锚文本用"点击这里"**：浪费每次内链的语义信号。

## Code Examples
```html
<nav aria-label="面包屑">
  <ol>
    <li><a href="/">首页</a></li>
    <li><a href="/guide/">入门指南</a></li>
    <li>关键词研究</li>
  </ol>
</nav>
```
- **What it demonstrates**: 面包屑导航——用户定位 + 爬虫理解结构双重作用（配合 BreadcrumbList 结构化数据更佳）。

## Reference Tables
| 场景 | 推荐 | 原因 |
|---|---|---|
| 同一主题的不同页面 | 子目录 | 共享域名权重 |
| 完全不同的关键词领域 | 子域名 | 独立站点，关键词聚焦紧密 |

| 架构 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| 扁平 | 深度浅、易抓取 | 难组织大量页面 | 小站 |
| 层级 | 结构清晰、可扩展 | 可能过深 | 大站 |
| 扁平化层级 | 两者兼得 | 需规划 | 推荐 |

## Worked Example
onl.jp（日本工具站）：年访问量 2361 万、51.87% 来自搜索，但仅 90 个索引页面。策略：用子域名为每个工具做独立站点，每个子域名聚焦一个关键词，关键词聚焦度极高。对照另一案例：1000+ 工具页面的站用 Screaming Frog 分析发现深度过深、内链混乱，通过分类重组、footer 链接面、面包屑优化后索引率和停留时间提升、跳出率下降。

## Key Takeaways
1. 所有页面 3 次点击内到达，重要页面 2 次以内。
2. 降不了深度就加宽度：footer 和分类页是深度救生员。
3. 同主题用子目录，跨领域用子域名（onl.jp 用 90 个页面做到 2361 万年访问）。
4. 每页 3-5 个描述性内链，重要页面多被链接。
5. 面包屑 + BreadcrumbList 结构化数据是标配。
6. URL 小写、连字符、简短、含关键词。
7. 后端渲染是架构优化的强制前提，先让爬虫看见内容。
